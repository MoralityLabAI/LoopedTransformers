# LSA-02K: Native-certified equality rewriting and dependent transport

**Registered November 24, 2026.** Development-only CPU pilot after [LSA-02J](../reports/lsa02j_branch_utility_cpu_20261124.md). The public Horn fixed-point control saturated the preceding benchmark. This experiment changes the proof problem itself: a candidate rewrite changes the term and therefore the subsequent set of legal rewrite occurrences.

## Formal task family

Let A be an arbitrary type, x : A, and f_a through f_f : A → A be six arbitrary unary functions. A word abc denotes f_a (f_b (f_c x)). Each public rule is a universally quantified equality between two different words of length two or three, applied to an arbitrary suffix z : A. Each direction is legal. A candidate consists of its equality index, direction, matching occurrence position, and resulting word. The state graph is implicit, and multiple rewrites can interact at overlapping occurrences.

There are two registered theorem families, with the same underlying distribution of rewrite systems:

- Equality: prove the source term equals the target term.
- Dependent transport: given P : A → Type and a witness : P(source), construct P(target) via the equality proof and Eq.mp (congrArg P eqproof) witness.

The second family involves actual indexed Type transport in Lean. It does not yet model dependent hypotheses that change the tactic grammar or arbitrary dependent elaboration.

All successful search paths must survive independent structured replay and compile as complete axiom-free Lean 4.19 declarations. Proof construction uses only instantiated public equality hypotheses, Eq.symm, congrArg under the prefix context, equality transitivity via calc, and Eq.mp for transport. The generator, simulator and renderer are distinct from the original Horn-only lgym REPL. No live native tactic calls are claimed for search attempts; the Lean compiler independently checks every retained terminal proof including its individual rewrite steps.

## Frozen cohort and evidence

Use generator seed 20261204. Generate 64 training roots, 32 calibration roots, 32 ordinary roots and 32 longer-word OOD roots. Every root has its own rule system, canonicalized across all six-symbol permutations, equality orientations and rule order. Roots are rejected only for invalid generator walks, insufficient endpoint difference, or duplicate rule-system lineage. Generation never filters on evaluated solver outcomes.

Each system has eight two-symbol rules and four three-symbol rules, with unique rule sides. Ordinary source words have length 10 or 11; OOD words have length 13. Targets are generated by a self-avoiding reversible rewrite walk of 10 (ordinary) or 12 (OOD) steps, with at least four changed positions. Reference witnesses therefore fit the 16-rewrite path cap. These witnesses are upper bounds on proof length; shortestness is not asserted.

Freeze public cases and source witness files with SHA-256 receipts. Only train witnesses are opened before model fitting. Calibration witnesses are opened after all policies have run and then independently compiled. No ordinary/OOD witness files are emitted; those splits are hash-checked but never scored in this pilot.

## Models, supervision and controls

Retain the original Plan B architecture (57,475 parameters, width 32, four heads, two AB recurrent passes, 384-byte byte encoder). Its public packet includes every rule, current word, target, family and remaining path budget. Each action token includes the public rule index, direction, occurrence and successor word. Refuse oversized packets/menus.

Training first runs an independent bidirectional BFS with a 32,768-edge cap on each train root. Use its certified witness when found; otherwise use the generator witness. The teacher labels every candidate reaching the next certified witness state positive. Other actions are unselected alternatives, not certified invalid or dead. Compile every full training witness in actual Lean before fitting.

Train seeds 197 and 199 on the same source-only witness frames, 720 AdamW steps each. Matched conditions are genuine witness imitation and within-frame shuffled-label sham. Preserve menus, positive count, source-root sampling stream, starting tensors, architecture, and optimizer budget. Repeat each of four fits exactly on one CPU worker with one Torch thread, deterministic algorithms, disabled MKLDNN. Fail if checkpoint and trace fingerprints differ or if the two arms have unequal initialization or sampling schedules.

## Budgeted search and preregistered endpoints

All policies use a 128-unit budget, one unit per considered legal successor (including previously visited states) and a maximum 16-rewrite proof path. Menu generation, model calls and expanded states are recorded separately. Policies have equal successor-work caps, not equal wall time or FLOPs.

| Policy | Priority |
| --- | --- |
| A* | g + ceil(Hamming distance / 3), then exact Hamming distance |
| Bidirectional BFS | Layer-synchronous smaller-frontier expansion from source and target |
| Random tie A* | Same admissible primary priority, seeded random candidate/tie priority |
| Learned A* | Same admissible primary priority, frozen witness-trained ranker for ties |
| Sham A* | Same primary priority, frozen shuffled-witness ranker for ties |

The bidirectional solver is the strong separate symbolic competitor; it sees the same rules and endpoints. Random A* uses five root-specific seeds 17,31,47,61,83. The neural models may only modify tie-breaking of the common admissible A* lower bound. The prior LSA-02I/J 16-unit DFS results use a different work definition and cannot be directly compared.

The **benchmark headroom screen** requires the strongest of A* and bidirectional BFS to close fewer than 95% of the 32 roots under the 128-unit cap. All 32 generator witnesses must independently compile. Failure indicates a saturated benchmark or a broken source; passing indicates bounded search difficulty rather than a general impossibility for classical algorithms.

**Development screen:** the learned arm must gain at least +5 absolute closure points over the stronger symbolic control and at least +5 points over its shuffled sham. The competence preflight separately requires ≥40% closure, ≥10 points over the stronger symbolic control and ≥10 points over random-tie A*. These are descriptive development gates. Use paired 2,000-draw bootstrap intervals clustered at the 32 independent theorem roots. Report equality and dependent transport subgroups, total/closed search work, model calls and proof-path lengths.

No training on calibration, ordinary or OOD states is authorized. Even a positive result requires separate prospective confirmation and a stronger grammar with genuinely dependent tactics before any architecture promotion or Mathlib transfer claim.

## CPU reproduction

From research/lean_cgrt_hrm400, after installing Lean 4.19.0 and CPU Torch 2.5.1:

    python -m ppt_gym.rewrite_gym freeze --out runs/lsa02k-suite
    python -m ppt_gym.rewrite_pilot --suite runs/lsa02k-suite --out runs/lsa02k-pilot

The dedicated GitHub Actions workflow runs unit tests, the complete source and model campaign on one CPU runner, and archives the native Lean declarations, source/model hashes, search receipts and paired results. No paid inference or GPU.
