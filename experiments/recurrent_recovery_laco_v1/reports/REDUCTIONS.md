# Reductions and deviations (kept up to date as runs complete)

| item | spec | what was done | why |
|---|---|---|---|
| model | small Qwen3, scaling toward 8B | **Qwen3-0.6B-Base** only (28 layers, d=1024) | the LaCo reproduction project pins the `*-Base` checkpoints, so Base is used (not the post-trained 0.6B). The machine had ~1-5 GB of the 16 GB VRAM and ~5 GB of 31 GB RAM free (other jobs), so 1.7B/8B were not attempted; 8B-Base and 1.7B-Base are already in the HF cache for a later run. The code path for 8B exists (`--quant 4bit`, shallow weight sharing between teacher and students, per-layer + per-loop activation checkpointing) but is **untested at 8B**; LaCo merge arithmetic at 8B would additionally need layer-streaming (as in laco-lab `ckpt.py`) because the bf16 weights do not fit in free RAM. |
| LaCo outputs | use the LaCo reproduction outputs | `load_laco_manifest` ingests a laco-lab `laco_recipe.json` (layout, weight/norm/qk-norm modes, delete ops). At the time of the runs the reproduction had produced no final recipe (only a baseline smoke eval), so **our own LaCo search** (`scripts/run_laco.py`, single collapsed range of m=7 layers, `last` merge = the official-notebook arithmetic, calibration = pile-10k train chunks) is the stand-in. Re-run with `--laco-recipe` once the reproduction project's recipe is final. |
| teacher | original transformer | Qwen3-0.6B-Base **+ LoRA (r=64) tuned on the synthetic tasks** (CE) with KL-to-base on text, merged. Untuned base is reported as A0. | the base model cannot solve the synthetic tasks, so "recovering algorithmic computation" would be undefined without a teacher that has it |
| context | - | train: 256 text tokens; tasks <= ~150 tokens. Eval: 256 and 1024 tokens text; task lengths beyond training range (FSM 32/48 moves, 9/12 digit add, 4-5 digit mul, chain depth 9/12) | 16 GB VRAM, shared GPU |
| steps | - | 600 (main), 300 (ablations), teacher 1200; batch 4x256 text + 8 task sequences; single seed | shared GPU / time. Differences of a few points on 64-example task sets are within noise (binomial s.e. ~ 3-6 points per set) |
| MC benchmarks | - | ARC-E, ARC-C, PIQA subsets (400 main / 150 ablations) from the local HF cache | s.e. ~ 2.5 points |
| trained loops | 1,2,4,8,16 | adapters trained for up to 8 loops, T sampled from {1,2,4,8} per step (`--t-sched pow2`); T=16 is **extrapolated** (last adapter reused) and marked as such | memory/time |
| quantisation | 4-bit | implemented (`--quant 4bit|8bit`, bitsandbytes 0.50 in `vendor/`), verified end-to-end (quantised student blocks + LoRA + grad-ckpt, tiny-model GPU test); **main runs are bf16** because the 0.6B model fits | 0.6B bf16 teacher+student ~2.5 GB |
