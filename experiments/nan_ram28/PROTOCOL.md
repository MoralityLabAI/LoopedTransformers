## File-backed loader and checks

All locked checkpoint files are verified with bounded streaming SHA-256.
The architecture is constructed on `meta`, then each checkpoint tensor is
backed by its own **read-only file mapping**. Windows copy-on-write mappings
are deliberately avoided: they reserve commitment for the entire view.
Tensor storage retains its mapping owner; no live tensor is manually unmapped.
The pinned embedding has no in-place max-norm update, gradients are disabled,
and this condition supports inference only. CPU parameters must never be mutated.
The existing bitsandbytes NF4/double-quantization conversion is used unchanged,
releasing mapped decoder storage as each layer becomes GPU-resident. The BF16
output head moves to GPU; the CPU embedding table remains file-backed.

Before the first pretrained forward, packed/native parameter bytes must match
the original CTX21 NF4 digest
`8e80e7d748d5daf858a0b37dd7843d38952554ce3aabea1104e52cf1ef7663b3`.
This does not independently establish old quantization-state identity or
output equivalence. GPU capacity/arithmetic checks and every later outcome
remain empirical. Final target mismatch is an explicit failure.

CPU-only checks cover exact synthetic BF16 materialization/forward, mapping
lifetime, read-only source preservation, invalid extents, RAM guard boundaries,
external PID counters, inherited scope and Windows commitment accounting.
A 128 MiB copy-on-write view increases commitment while the read-only view

Use the existing pinned packages, snapshot and GPU; no downloads/cloud inference.
One large model, one numerical CPU thread, Below Normal priority. Start only
with at least4 GiB available physical RAM and no known model/host worker.
Between captures require at least2 GiB available and at most6 GiB private
worker commitment. The private cap is below the former11.626 GiB commitment;

in-flight orphan and no normal receipt; preserve it, do not invent completion.
