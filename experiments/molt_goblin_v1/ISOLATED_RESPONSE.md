# MOLT-11: isolated exact response storage and training

Development engineering continuation of [MOLT-10](RESPONSE_FACTOR_RESULTS.md).
The four mathematically equivalent response loss representations are isolated
in separate Linux processes. This measures actual single-process RSS and
training time, rather than inferring hardware savings from tensor counts.

## Native answer path

The fully tied reset-carry LOOP-T word is unchanged. At each visit the native
block operates on the complete causal sequence state. The new path computes
the final-normalized answer state at each visit and materializes only answer
vocabulary logits for the task and trace losses. The patched branch injects
the additive native BPD-span write before the model's native residual beta.
It does not need to materialize vocabulary logits in the Gram arm. Compare
against the actual full decoder and trace loss, including gradients through
all physical weights. The test uses a nonzero patched response. This helper
is restricted to the declared fully gradient-visible reset schedule; it
must not be reused silently for arbitrary truncated or checkpointed schedules.

## Fixed engineering roster

Fresh generated AUX-V2 modular-recurrence TRAIN/validation data, seed
2026112711, train quota 4, validation quota 2. The teacher uses 256 updates
and a tiny native BPD fit (4 factor steps, 2 warmup, no null calibration).
The held splits generated by the dataset builder are never opened in the
worker. Teacher and factor fit are existing engineering commands in CI;
the isolation supervisor caps the subsequent preparation/training/audit
workers, not those pre-existing setup commands.

Before any continuation, record teacher validation exact accuracy, class
macro recall and the constant baseline. The competence gate is exact
accuracy >=0.25 and lift >=0.10 over the constant baseline. There is no
teacher selection, retry-until-competent, or sealed evaluation. CI explicitly
runs engineering parity even if the gate fails. The operator can require
competence with --require-competent, which stops after the common preparation
receipt when the gate fails. Passing it would still not establish a learning
benefit, because all compared objectives are equivalent and there is no
ordinary task-only causal control in this engineering panel.

At depth 8 use 8 distinct TRAIN anchors, 32 distinct TRAIN donors per anchor,
one physical write at visit 4, 256 records total, 16 student updates, batch 4.
These are cross-item displacements with no source-valid donor claim. A separate
worker builds the common immutable native output-span coordinate archive.
Each target preparation process stores just one representation, dense or
factored. The factor archive includes its separate frozen centered teacher
head. The Gram arm separately builds its teacher Gram. Recompute retains the
complete frozen teacher and its centered head and loads no target archive.
All four training processes start from the same teacher weights, native
coordinate archive and RNG schedule. No process intentionally loads more than
one of the dense/factor response archives. Archives coexist on disk, outside
the process RSS accounting.

The final separate audit checks source/common/checkpoint hashes, roster and
schedule consistency, training and auxiliary loss differences, final parameter
parity, and all ordinary validation predictions. All objectives remain the
full centered vocabulary response MSE; the student head is trainable. No
teacher Jacobian is applied to student gradients.

## Resource contract

Linux only. The parent process imports no PyTorch. Sequential fresh workers
have a hard per-process virtual address-space limit (8 GiB in CI), a hard CPU
time limit (180 s), and a 240 s wall deadline. One intra-op and one inter-op
PyTorch thread; BLAS/OpenMP thread environment set to one, GPU disabled.
The supervisor samples /proc RSS/HWM/virtual size every 25 ms and kills the
process group on an observed child, guard violation (2 GiB RSS), or timeout.
The worker also reports Linux kernel ru_maxrss. The sampled guard is not a
kernel-enforced physical-memory limit or guaranteed process-tree monitor;
short-lived children could escape observation. Hard address space is a
different metric from resident memory. Run under the operator's cgroup or
Job Object wrapper for enforced process-tree RAM. Teacher fitting, package
installation, parent, and unrelated processes are outside the worker caps.

Each phase receipt records actual elapsed time, sampled memory peaks, hard
limits, exit status and log. Each training arm reports lifetime RSS after
load/training, CPU and wall training time, common/response/Gram payloads,
extra teacher parameters and response head, and work counts. Lifetime peak
includes import and allocator transients; it is not an incremental RSS charge.
Target preparation time and file sizes are separate. These are fixed-order,
one-run engineering measurements; OS cache, allocator and CI noise remain.
No promotion, statistical or task-training efficacy claim.
