`LOOP-T-aux2cpu-s1` and `LOOP-T-modnccpu-s1` are CPU cells; they are paused or running slices and are included as they stood at the snapshot.

**`modular_recurrence` does not train under the curriculum.** At depth 1 the training pool has 131,435 examples but only 2,448 distinct inputs, and none of the 211 validation depth-1 inputs occur in it (`modular_check2.out.txt`). A checkpoint solves depth 1 on the training pool (0.996) and not on validation (0.09 to 0.10), so it memorises those inputs, and the curriculum, which unlocks the next depth on validation accuracy, never leaves depth 1. At depth 2 the pool has 112,982 distinct inputs in 124,458 examples and at depth 8 all 123,910 are distinct; `masked_pointer_chase` has all inputs distinct at depths 1, 2 and 8 and shows no such gap. A no-curriculum run (`LOOP-T-modnc-s1` on GPU, `LOOP-T-modnccpu-s1` on CPU) tests whether it learns at all without the depth gate.

## 3. Training throughput on this machine

Per step: batch 256 per family x 2 families (512 sequences of 64 tokens), 8 visits, deep supervision. Model: 459,776 parameters.

| Setting | Result | Source |
|---|---|---|
| CPU fp32, 4 / 8 / 12 / 20 threads | 0.17 / 0.30 / 0.31 / 0.23 steps/s | `scripts/cpu_throughput.py` (interactive run, output in session only) |
| CPU, bf16 autocast vs fp32, 30 steps | 1.90x faster (5.52 s vs 2.90 s per step, measured while another CPU job ran); loss over the last 20 steps 3.2598 vs 3.2603 | `bf16_bench_cpu.json` |
| CPU bf16, long run `LOOP-T-aux2cpu-s1` | about 0.8 steps/s sustained (20,000 steps in about 6.8 h) | `cells/LOOP-T-aux2cpu-s1/events.jsonl` |
| GPU fp32 | 10.01 steps/s, peak 1597 MiB allocated | `bf16_bench_gpu.json` |
| GPU bf16 autocast | 9.35 steps/s (0.93x of fp32, not adopted); loss over the last 20 steps 2.4697 vs 2.4698 | `bf16_bench_gpu.json` |
| GPU microbatch 64 / 128 (batch 256 accumulated), `masked_pointer_chase` only | 353 / 681 MiB peak, 3.9 / 8.9 steps/s | inline probe, not stored |

The bf16 switch is an environment flag (`RMP_BF16=1`) in `research_gym/interp/training.py`; weights, optimizer state and checkpoints stay fp32 and cell identity is unchanged. Default is off.

CPU profile of one training step (`cpu_profile_fp32.out.txt`, `cpu_profile_bf16.out.txt`; 8 threads): in fp32 `aten::mm` is 49.1% of CPU time (2.47 s over 242 calls, about 10 ms each, roughly 340 GFLOP/s, near this CPU's fp32 peak), `bmm` 7.5%, `copy_` 5.6%, `mul` 5.4%, of 5.03 s total. In bf16 `mm` falls to 31.8% (1.04 s) while `copy_` (dtype casts) rises to 11.7% (0.38 s); total 3.25 s. Training sequences are 64 tokens with about 68% padding (0.683 of tokens in the training pool, 0.664 in validation, from `modular_check.out.txt`). Skipping padded positions is a compute reduction that is independent of kernel speed; it was not tried, and the answer sits at the final position (63) behind that padding, so it needs a layout-equivalence check before it can be used with these recipes.

## 4. LBF-20M local reproduction (PR 383, source `40824b86e72da8fe54874ec9d9619d41b2706488`)

Five sequential repetitions, all exit 0, Python 3.12 instead of the registered 3.11, Lean 4.19.0 compiles with six axiom-free declarations. Every repetition passes 32 local receipt checks (`verify_local.py`): 56 systems, 32,768 worlds, 1,944 queries, 5,832 support checks, 168 label-map comparisons, 62 roots, 372 rows (298 exact, 74 caps), 1,614 exact comparisons, 342 oracle queries (96 fresh), task digest `dbc74a0dae5bd1f5e1d2ca4079b07e256579caa07bc53fdad8c130601f088107`. No non-timing field differs between repetitions.

|---|---:|---:|---:|---:|
| `mdd_forest` | 11,209,296 | 0 | 21,779 | 588 |
| `mdd_components` | 965,184 | 0 | 3,099 | 285 |
| `mdd_query_cache` | 965,184 | 225,396 | 1,849 | 276 |

On the 50 retrospective roots component caching saves 16 nominal bits with the same 4,782 messages; query memoization stores 1,661,860 extra bits for 15 hits. Full tables and row-level timings: `local_reproduction_20261125/REPORT.md`, `summary.json`, `row_timings.csv`.

Not verified: the bundled verifiers, the inherited 20L receipts, the independent fresh reference and the original CI archive were not available (`lbf20m-run-and-audit.zip` was not found on the machine), so the 50-case identity with 20L, fresh answers against the structural reference and the diagram fixture check were not run. Wall time per repetition varied from 374 s (a preliminary attempt) to 657 s; the cause was not isolated.
