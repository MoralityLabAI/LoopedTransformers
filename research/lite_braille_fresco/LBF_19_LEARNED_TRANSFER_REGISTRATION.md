# LBF-19 Track R Registration — Learned Recurrent Transfer Functions (development-only)

**Status:** development-only research direction, separate from the LBF-18 sealed-confirmation chain. Nothing here changes any LBF-18 claim or checkpoint. Registered **before any test-set scoring** (the test split is generated by code but never scored or inspected before this file is pushed).
**Branch:** `research/lbf19-expensive-verifier-20261125` (based on merged LBF-18 PR #349, `f2ffca19`).
**Motivation:** Independent referee report §10 ("compact recurrent reasoning") and §13 rank 7: in LBF-17/18 the recurrent transfer function is hand-written. Can a small recurrent cell *learn* it, and does it extrapolate?

## 0. Epistemic status (stated up front)

* **Boolean support remains the proof-relevant object.** Theorem A/B are about the exact guarded Boolean `u64` support. A learned network output is **only a ranking / approximation signal**, with **no soundness claim**, except for the explicitly constructed *hard-sound* readout (§3), whose Boolean output is sound by construction (it is a mask computed by exact Boolean operations, not by learning).
* The learned arms are *trained to imitate* the exact guarded transfer. A failure to match is a negative result about learnability/extrapolation, not about the theorems.

## 1. Target object

For a rule system `R` (alphabet `abcdef`, equal-length oriented rules, lhs length 2 or 3), start word `w0` of length `L` and horizon `K`:

`Y_K(R, w0) ∈ {0,1}^{L×6}` = position-symbol projection of `base_a2 ∪ ⋃_f fiber_f` after `K` passes of the repo's exact guarded transfer `lbf18_incremental_fresco.symbolic_prov_adj2_guarded(R, w0, k_max=K, fp=4, guard_mode="fable_len_guard")` (the `prov_adj2` Boolean bigram-support map after `K` rewrite passes; projection to symbols as in `u64_supp_to_pos1_bool`, additionally unioned with the start word's own symbols, which are trivially reachable at `K=0`). `Y_0 = onehot(w0)`. The model is supervised/evaluated on `Y_k` for `k = 1..K`. The exact transfer iterated `K` times **is** the ground truth and arm (e).

## 2. Data generators (fixed seeds, disjoint by canonical lineage)

* **Rule systems:** `n ∈ {3,4,5}` unoriented rules; each lhs has length 2 (p=0.6) or 3 (p=0.4), uniform random over `abcdef`; rhs is a uniform random string of the same length `≠ lhs`; duplicate lhs within a system rejected.
* **Canonical lineage key:** minimum over all 720 alphabet permutations of the sorted tuple of sorted `(lhs,rhs)` pairs (invariant to alphabet renaming, rule order and rule orientation). Splits are generated in the order test → val → train; a candidate whose canonical key already occurs in any split (or earlier in the same split) is rejected. **Train / val / test rule systems are disjoint by canonical lineage** (asserted in code and in the test-suite).
* **Seeds:** system generation `python random.Random(seed)` with test `19110003`, val `19110002`, train `19110001`; word sampling uses `Random(seed ^ 0x5eed)` of the respective split; model training seeds `0,1,2,3,4` (torch + data-order).
* **Words:** 50% uniform random over the alphabet; 50% "planted": uniform random with 1–3 randomly chosen oriented lhs/rhs windows overwritten at random positions (guarantees non-trivial rewriting at long `L`).
* **Sizes:**
  * train: 400 systems × 8 words, `L ~ U{8..12}`, supervised on `k = 1..3` (so **train K ≤ 3, L ∈ 8..12**).
  * val: 80 systems × 4 words, `L ~ U{8..12}`, `k = 1..3` (in-distribution only). Val is used for **threshold calibration, model-selection of the final epoch (none: fixed budget), and nothing else**.
  * test: 100 systems ("roots") × 2 words at each `L ∈ {8, 10, 12, 16, 20, 24}`, `k = 1..8`. In-distribution cells: `L ≤ 12, K ≤ 3`; extrapolation cells: `K ∈ {4..8}` and/or `L ∈ {16,20,24}`.

## 3. Arms

All learned arms: PyTorch, CPU, `torch.set_num_threads(4)`, ~20–60K parameters, same optimiser (Adam, lr 3e-3 cosine, 1,500 steps, batch 64 words, BCE with `pos_weight` fixed at 1), **same data and budget; hyper-parameters fixed here and never tuned on test**.

| id | arm | description |
|---|---|---|
| a | `rec_prior` | weight-tied recurrent cell unrolled `K` times; rules encoded by a learned rule encoder; **zero-preserving, support-gated update**: `y_k = max(y_{k-1}, G(y_{k-1}) · u_k)` where `G` is the parameter-free soft-AND support gate of the (oriented, padded) rules over the previous learned support, so cells whose rule windows are unsupported are exactly 0 |
| b | `rec_noprior` | identical cell, no gate and no union: `y_k = σ(readout(h_k))` |
| c | `nonrec_param` | non-recurrent, single application, width enlarged so **parameter count ≈ arm (a)**; horizon given as scalar input `k/8` |
| d | `nonrec_compute` | non-recurrent stack of 3 untied copies of the cell (≈ **FLOPs of 3 recurrent steps = training K**), horizon as scalar input |
| e | `oracle` | exact symbolic guarded transfer (zero parameters; FN = 0 and precision = 1 by definition; reported for CPU cost) |
| a-hs, b-hs | `rec_prior_hs`, `rec_noprior_hs` | arms (a),(b) trained and run with the **hard-sound masked readout**: `y_k ← y_k ⊙ U_k` every step, where `U_k` is the exact Boolean one-step-window hull of the start word (iterating the exact pos1 rewrite hull `K` times, computed with Boolean ops, never learned) |
| hull | `pos1_hull` | the arm-independent Boolean `U_k` itself (sound over-approximation if `Y_k ⊆ U_k` — checked empirically on every split, violations reported, not assumed) |

**Hard-sound output (definition).** The Boolean hard-sound output is `U_k`: it contains `Y_k` structurally (false negatives impossible), and the learned score only *ranks cells inside `U_k`*. A thresholded learned score inside `U_k` is **not** sound. Everything else in this track (learned logits, thresholded or not, including the masked-readout arms thresholded at `τ`) is an approximation without a soundness claim. Non-recurrent arms get only a post-hoc mask `⊙ U_k` (reported as `*_masked`), no in-loop version.

Confound disclosed in advance: arms (c),(d) have no prior, so "recurrence helps" is tested **b vs c, d** (both without prior). `rec_prior` vs nonrec-with-prior is **not** tested.

## 4. Metrics (per arm, per `(K, L)` cell)

For each test word and `k`, compare predicted cells to `Y_k`:
1. **Support recall / false negatives:** (i) at strict `y > 0`: count of true-support cells with `y == 0`; (ii) at calibrated threshold `τ`: cell recall `TP/(TP+FN)`, and word-level rate of words with ≥1 false negative.
2. **Precision / over-approximation:** precision `TP/(TP+FP)` at `τ`, and size ratio `|pred|/|Y_k|`, against the exact guarded transfer iterated `k` times. Also precision at strict `y>0`.
3. **Ranking (threshold-free):** average precision (AP) of the score over all `L×6` cells, and AP restricted to cells inside `U_k` (ranking-in-hull); base-rate-adjusted lift over hull precision.
4. **Calibrated threshold:** one `τ` per arm: the **largest** `τ` such that pooled in-distribution **val** cell recall (k=1..3, L 8..12) is ≥ 0.99. It is applied unchanged to all test cells. No threshold, hyper-parameter or arm selection uses test data; extrapolation cells receive the same `τ` (threshold-free AP is reported alongside, because a fixed `τ` can shift under extrapolation).
5. **Extrapolation curves:** recall, precision, AP versus `K ∈ 1..8` (at `L ∈ {8..12}`) and versus `L ∈ {8,10,12,16,20,24}` (at `K=3` and `K=8`).
6. **Cost:** training wall time (s) and parameter count; inference CPU time per word (ms) vs oracle CPU time per word, per `L` and `K`.

**Aggregation / statistics.** Unit of analysis for paired contrasts: the **root (rule system)** — mean over its words, then paired differences across the 100 test roots, with 95% bootstrap CI (10,000 resamples, seed `19110099`). Seed-level: ≥5 training seeds for every learned arm; report mean ± sd over seeds, and seed-level paired contrasts (same seed index) with 95% CI (t-interval over the 5 seeds). Root-level contrasts use the seed-averaged per-root metric.

## 5. Hypotheses and pre-set pass/fail criteria (decided before test scoring)

Let "recall" = cell recall at `τ`, "prec" = precision at `τ`, both averaged over roots then seeds.

* **H1 — learnability (in distribution):** `rec_prior` at `K=3, L≤12`: recall ≥ 0.98 **and** prec ≥ 0.90. *Pass* if both; else *fail*.
* **H2 — horizon extrapolation:** `rec_prior` at `K=8, L≤12`: recall ≥ 0.95 **and** prec ≥ 0.80. (Collapse = recall < 0.90.)
* **H3 — length extrapolation:** `rec_prior` at `L=24, K=3`: recall ≥ 0.95 and prec ≥ 0.80.
* **H4 — prior helps:** paired root-level difference `rec_prior − rec_noprior` in **AP** at `(K=8, L≤12)` and at `(L=24, K=3)`: both 95% CI lower bounds > 0 ⇒ *prior helps*; both CIs containing 0 ⇒ *no detectable effect*; negative ⇒ *prior hurts*. (AP is the primary contrast because recall/prec depend on a per-arm `τ`; recall and prec contrasts reported as secondary.)
* **H5 — recurrence helps:** paired root-level AP difference `rec_noprior − nonrec_param` and `rec_noprior − nonrec_compute` at `(K=8, L≤12)` and `(L=24, K=3)`; interpretation as in H4. Also reported with prior on the recurrent side (`rec_prior − nonrec_*`) as a descriptive, confounded contrast.
* **H6 — hard-sound readout:** (i) `Y_k ⊆ U_k` for 100% of test words/k (else the mask is *not* hard-sound for the guarded adj2 target and the variant is reported as failed); (ii) `rec_*_hs` strict-`>0` false negatives = 0 by construction; (iii) in-hull AP lift over the hull's own precision > 0, with root-level CI. The honest cost: the sound Boolean output is exactly `U_k`, whose precision is arm-independent; learned scores buy ranking only.
* **H7 — cost:** report whether any learned arm is cheaper at inference than the exact Python oracle per word at each `L`; no pass/fail threshold.

All hypotheses are reported regardless of outcome. Negative outcomes (recall collapse at large `K`/`L`, prior or recurrence not helping) will be stated as such. No claim of "learned transfer is sound" will be made for any non-hard-sound arm.
