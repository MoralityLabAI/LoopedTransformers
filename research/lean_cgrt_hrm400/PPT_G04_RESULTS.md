# PPT-G04 native Lean pilot

PPT-G04 demonstrated verifier-grounded FP32 updates, atomic resume, and exact replay in the Windows CPU process tree. The initial Micro and Tiny comparison found no SGD gain over frozen or retrieval at the 16-support dose. In a separately frozen, budget-feasible Micro follow-up, SGD certified 3 of 12 roots, frozen and retrieval each certified 4, shuffled feedback certified 2, and Horn automation certified all 12. All reported completions were accepted by the Lean 4.19 kernel and independently compiled without axioms.

The primary observational unit is a generated theorem lineage. Repeated doses, architectures and arms reuse the same roots. Original RAM-02 has three final-dose lineages and two solvable within the tactic budget. The shuffled control permutes labels within each support episode, so constant-label episodes give it the same update as SGD. The five-point minimum meaningful improvement, sham envelope and independent-family generalization remain unresolved at this pilot scale. The feasible follow-up uses distinct lineages under a preregistered reference-cost filter and remains a descriptive pilot.

## Resource audit

All sessions used `torch 2.7.1+cpu` with FP32 master weights, zero GPU allocations and two configured CPU threads. Windows Job Objects enforced the 2, 4 and 6 GiB private-commit ceilings across each process tree. Across successful campaign runs, peak commit reached 517 MiB and sampled process-tree residency reached 617 MiB. A separate inherited-limit probe accepted a 32 MiB child allocation and denied a 2 GiB child allocation within the occupied 2 GiB job. The Windows peak counter includes denied allocation requests, so that probe's peak is a requested commit value. The audit includes process-tree CPU utilization, Lean latency, training throughput and per-pass model timings. Per-pass CPU time is quantized by the host accounting clock. Estimated MACs and measured elapsed costs are both retained.
