## Implementation and interpretation

`audit/rlt_long_prepare.py` freezes inputs; `lcgrt.rlt_long` runs one lane; `lcgrt.tactic_lm --continue-from --stop-at` retains optimizer state and stops chunks without changing the recipe identity; `lcgrt.mathlib_eval --states-file` prevents resampling. CPU tests verify optimizer-step retention, parent immutability, global data indices and exact chunked/uninterrupted equivalence, plus frozen-cohort rejection and matched snapshot selection.

This is one longer training seed per architecture and a small fresh cohort. A byte-loss improvement, lower raw norm, or diverse but invalid output does not establish better proof reasoning. Compare RLT against damping as well as direct feedback. Q5 F1/F8 and task-length extrapolation are not measured by this experiment; the original classifier and the 400M no-go remain unchanged.

Resource amendment during the first continuation chunks, before fresh outcomes: the host was at 100% CPU with GPU utilization about 13%, GPU temperature 69C and 10.31 GiB RAM available. The owned launch workers received roughly 55% and 15% of one CPU core in the sample. Resume the two owned jobs at above-normal CPU priority, retaining two torch threads each and all existing duty/memory/thermal limits. Original manifest start times still bound the lanes to 230 minutes each. This affects scheduling, not the fixed model/data/optimizer recipe. Record checkpoint positions and any unquantified unsaved work; do not use shared-host wall times to infer feedback overhead.

Second resource amendment, before fresh outcomes: the 78°C soft controller repeatedly reduced duty to 0.1; HRM throughput fell from about 0.46 to 0.13 steps/s, with the GPU later sampled at 75°C and 6% utilization. Raise only the soft threshold to 80°C, retaining the 85°C hard pause, maximum duty 0.5, memory limits, original elapsed caps and the exact training recipe. Record both resource segments and checkpoint resumes.

Checkpoint-cadence amendment during an AC/power-cap pause, before fresh outcomes: shorten remaining segments to 100 updates to reduce incomplete, unmatched work at the cap. First catch every arm up to the furthest saved optimizer step in its architecture, then rotate 100-update segments, ending exactly at the fixed 6,000-update horizon if reached. Keep parent states, batch/data stream, LR schedule and all optimizer updates unchanged. Select the largest completed common snapshot, now at the finer cadence. Snapshots without a validation event record null validation loss; final diagnostics still score the same fixed sample. Calibration diversity probes run at the first common snapshot crossing each 1,000-update threshold. This deterministic budget-use change never reads fresh outcomes; preserve the original frozen protocol plus this dated amendment and resource segments.

Power-budget amendment: both lanes saved optimizer checkpoints and paused when Windows switched to battery and enforced a 45 W GPU cap. Exclude this externally forced, recorded power-off waiting interval from the eight-hour **training** allowance. Keep the 230-minute per-lane allowance; thermal backoff, CPU contention and scheduling restarts still count. Store outage start/end evidence separately from the frozen protocol, merge overlaps to prevent double credit, and record both wall elapsed time and excluded power time. Close an outage only after verifying AC/power-guard recovery; never train while its record remains open. This preserves the remaining authorized work rather than resetting the budget.
