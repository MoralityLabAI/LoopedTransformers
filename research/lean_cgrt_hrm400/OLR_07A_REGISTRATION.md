# OLR-07A: native library receipt-conditioned tactic allocation

Registered 2026-11-24, before collecting new tactic outcomes. Parent [06H results](OLR_06H_RESULTS.md). The finite opaque rewrite allocation family is closed after its negative gate.

## Motivation and contract

Real Lean library goals offer a setting where exact search over a small public transition graph does not supply all useful semantic knowledge. Existing lcgrt Mathlib c4 evidence reports 588 scored states, automation close@8 .5221, human close@1 .9592, and loop/TRM readers below the automation baseline. These published summary numbers motivate the task, not a new held-out score. The private HF raw traces are not assumed accessible. Start with original source files from the pinned Lean core library; later use actual Mathlib snapshots with appropriate file/family separation. No synthetic Boolean or hidden receipt bit.

Question: under four paid attempts at the same original goal, does observing the native rejection diagnostic or open-goal count improve a subsequent tactic choice beyond observing only failure? A receipt identifies source revision, declaration, position, full pretty-printed initial goal, action and its native result. Every tactic trial is speculative from the unchanged original goal. An open result is not committed. Failed or uncertified results are budget-specific observations, never proofs of impossibility. Native receipt history is exact host storage. If useful conditional headroom exists, a future tied recurrent reader estimates action value given actual goal syntax and the evolving receipt ledger. No recurrence is fitted in this preflight.

## Controls and evaluation

All controls have identical 4-attempt cap, stop on first native-certified closure, no duplicate attempts. The full menu envelope is an offline ceiling, not deployable.

- Exact best fixed order: maximize TRAIN coverage at four calls by enumerating all 4-element subsets. Within the winning set greedily order by remaining coverage to reduce early calls. The subset objective is exact; order cost is heuristic.
- Source empirical decision tree, exact finite-horizon recursion over the empirical TRAIN outcome table: belief is set of source rows still matching observations. At each decision maximize number of eventual closures under remaining calls; tie by lowest expected attempts then menu index. Failed branches partition the source subset by a coarse observed diagnostic category. Out-of-support observation backs off to all TRAIN rows consistent with observed history, then all TRAIN rows if still empty.
- Same empirical tree with binary nonclosure only.
- Goal-local empirical variants: initialize the same two trees from the 24 TRAIN goals with highest Jaccard similarity over deterministic complete goal lexical token sets. Ties by stable source identity. Both diagnostic and binary variants see identical goal text, menu and prior cohort. No source theorem proof text in policy features.
- Frozen best among the deployable controls on calibration closure@4 (ties lower mean attempted calls then arm order). The fresh evaluation is reported without additional tuning.

The native full-menu table is offline grading data: freeze TRAIN, then all controls are defined from TRAIN and calibration only. Simulate an adaptive policy by revealing only its selected next receipt, paying one attempt; the policy never sees the rest of the fresh row. No speculative side effects persist. Failure category includes parse, resource exhaustion, type/unification, no-progress/no-match, open goals (count bucket), other rejection and uncertified closure. Raw error text also retained for later models. No claim of independent proof compilation beyond the existing Trace.lean kernel certificate and fresh re-elaboration/replay. Report source human validity, candidate coverage, exact fixed subset, per-family rates, root-level action journals, total calls and wall time. Whole file/family is the transfer unit; descriptive root metrics alone do not establish powered generalization.

Gate: valid native bank, full-menu ceiling at least 10 pp above the strongest deployable four-call control on calibration and evaluation, and at least 20% of scored fresh states remain unsolved at four calls. Report diagnostic-vs-binary paired differences separately. No architecture promotion, training, FSI-01 pass, or claim about Mathlib generalization. If no useful headroom, close this tactic menu; do not force another learned cell.
