# InkyNano Stage 2 specification

Stage 2 tests packed expert residency and activation-aware compression as separate interventions. Start with individual experts and a bounded layer subset. Treat model-wide inference as a later experiment after correctness and memory measurements.

## Native packed residency

- **Storage and accounting.** Build an index from the pinned safetensors metadata keyed by `(physical_layer, expert)`. Each entry gives the file offset, dtype, block layout, weight bytes, scale and outer-scale metadata, alignment and digest. Keep the expert bank disk-backed on the 6 GB-free workstation. Use bounded read buffers and a bounded CPU cache. Charge pinned staging, allocator reserves and the largest tile workspace against the host/GPU budgets. Passes 0–2 share the same cache key.
- **Sizing.** The two native projections contain 7,962,624 elements per expert. The receipt reports 20 NVFP4 and four MXFP8 layers, yielding payload floors of 0.831, 1.661 and 3.322 GiB for 8, 16 and 32 slots per physical layer. Add scales, alignment, the backbone, prefill/decode activations and context-dependent caches. Even the 0.811 GiB optimistic backbone estimate plus the 32-slot payload floor exceeds 4 GiB. Use Stage 1 demand to test smaller per-layer byte allocations as well as equal-slot controls. Measure clean-card free VRAM before setting a working budget.
- **Loader parity.** Validate offsets and strides independently against the native inventory. Compare per-expert slices across both layouts and loop boundaries, including destination-dtype casting of scale metadata before dequantization, fused gate/up interleaving, native soft caps, sigmoid and FP32 accumulation. Use the pinned implementation as reference and record max absolute, relative L2 and original native mixture outputs. Test short reads, hash mismatch, access to an unadmitted expert, and repeated visits to a shared key. Compare CPU reference with Ampere-compatible GPU tiles dequantized to a supported dtype, with no full-bank dequantization or persistent dense copy.
- **Cache protocol.** Allocate fixed GPU byte pools before replay. First measure synchronous read, H2D and compute. Then test bounded double buffering and pinned staging with CUDA events. A slot becomes resident after its copy completes, and eviction waits for its last consumer across loop visits. Record failed admissions and every copy, including retries and warm-up. Make cache transitions atomic at window boundaries. For room shared by unequal expert sizes, use a byte-constrained admission rule and verify it against exhaustive small cases.
- **Router interventions.** Preserve the original sigmoid, ranking bias, scale and weighting. Separately test (a) the original selected experts intersected with the resident set, with explicit handling of zero surviving mass, and (b) native top-8 restricted to resident logits. With eight slots, the latter fixes expert membership within a segment. Compare fixed, periodic and adaptive controllers using availability and timing measured at each boundary. Count prompt prefill transfers, and test both full-information prompt features and a causal low-cost prompt predictor. Replace offline past-teacher inputs with available on-policy student observations and quantify the resulting shift.
- **Benchmark.** Run identical looped-layer inputs for native CPU reference, packed GPU tiles and an existing quantized/offload baseline. Sweep batch 1 and context 512/1024/2048 where feasible, with cold and warm caches. Measure disk bytes, H2D/D2H bytes, host working set, allocated/reserved and device-level GPU memory, prefill time and p50/p95 per-token latency. Isolate packed representation and router restriction before combining them. If a text-only composed runtime fits, evaluate restricted routing on independent development tasks with identical decoding settings and report native and restricted task scores by root.

## Activation-aware spectral refinement

1. Use the same 16-expert strata as the pilot where possible, spanning early/loop/late layers, both native formats, and typical/rare experts. Capture bounded train-only pre-expert activations and original native mixture coefficients from independent roots. Include each loop pass, report coverage by expert and pass, and reserve distinct development root families. Record the pinned model/exporter revisions and the calibration roster digest.
2. Compare native packed reference, the existing unweighted nested SVD, and activation-aware initialization at the same measured total bytes. For each gate/up projection, estimate an input second moment using bounded batches and damping, or a low-rank sketch. Fit weighted low-rank factors by minimizing the expected projection residual under that moment. Train the down projection on native post-gating activations. Keep source dtype and nonlinear treatment fixed across controls.
3. Refine gate, up and down factors jointly on the actual nonlinear expert output. Optimize normalized output error, weighted by the teacher's native mixture coefficient where available, and monitor unweighted per-expert errors as well. Train in small batches on fixed captured inputs, preserve exact nonlinear semantics, and avoid reconstructing a dense matrix during factor inference. Record seeds, rank, damping, loss weights and early-stop rules. Test 32/64/96/128/192/256 only where informative under the byte cap, and compare FP16 with block-INT4 using independently calibrated scales.
4. Measure held-out relative L2, cosine distance, high-percentile per-root error and weighted mixture-output error, along with packing, tile workspace, transfer and runtime costs. The existing rank-256 SVD means (0.8876 FP16 and 0.8946 INT4) came from one activation root. Re-estimate that baseline on the same held-out roots before judging improvement. Batch-1 task accuracy and stability require separate composed-runtime measurements.
5. Expand only after the packed layer path has numerical parity and the refined factors show a repeatable byte–fidelity advantage over unweighted SVD on multiple development roots. Compare against native packed weights at the same measured footprint and include projection metadata, workspaces and scales. Keep Stage 2 code and receipts explicit about which layers, experts, roots and passes ran.
