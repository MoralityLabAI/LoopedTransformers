# Prime local budget continuation policy

Registered after NF4 completed and after partial BF16 replies were visible,
before any continuation inference. The original NAN-PRIME-06 source seal, server,
limits, all outputs and primary receipts remain unchanged. This is an operational
supplement on exposed development sources, not a prospective confirmation claim.

Wait for the actual primary supervisor handle and every known primary model
process to exit. If all 162 tasks per backend have successful completed official
episodes, do nothing. Otherwise allow at most ONE new bounded worker per affected
backend, using the UNMODIFIED frozen server and the same pinned checkpoint,
template, greedy full-vocabulary decoding, schema caps, EOS, 7200-second service
budget, official SDK, local subprocess/null harness and 600-second rollout limit.

Select only tasks without a successful completed official episode. Include every
successful zero-reward or invalid-format answer as already finished: never use
correctness, format, reward, gold, losses or geometry to decide retries. Preserve
failed/timeout episodes and every existing neural reply. Any communication retry
gets fresh model computation and explicit attempt provenance; no response replay
or retry-until-correct policy. Use unchanged source order with an ID inclusion
file kept local. Do not access any other dataset, especially the protected 168.

Write the continuation server, traces, selection receipt, counters and failures
under distinct local directories. A subset worker may legitimately report its
own incomplete 162-context coverage; do not rewrite that receipt as complete.
Audit primary and supplemental attempts separately and the unique-task union,
counting duplicated task attempts as repeated observations, never new roots.
If the bounded tail also fails, record missing/failed coverage rather than
inventing accuracy or silently launching a third attempt.

The fitting queue waits for this supervisor as well as actual model termination.
One large model runs at a time. Publish aggregate coverage and hash evidence;
local routing IDs, prompts, replies, tokens and vectors remain local. No cloud
runtime, hosted inference, model downloads or test unseal.
